# План полной реализации квиза

Документ для диплома и разработки. Статус: реализация закрыта, осталась живая проверка на машине.

## Продукт

Онлайн-квиз в формате шоу:

| Клиент | Кто | Что делает |
|---|---|---|
| **TV** (`apps/tv`) | Приставка / большой экран | Пароль показа, лобби, QR, код на всём эфире, раунды, вопросы, реклама, рейтинги, подиум |
| **PWA** (`apps/player`) | Игроки | Вход по QR/коду, аккаунт, конструктор аватара, таблица рейтинга |
| **API** (`apps/api`) | Сервер | REST + WebSocket, почта, web push, очки, достижения |

Гость может зайти в комнату по коду без аккаунта. Рейтинг, медали и аватар копятся только у подтверждённого пользователя.

## Роли

- **PLAYER** — играет, профиль, аватар, достижения. Новый аккаунт всегда PLAYER. Ведущим из профиля стать нельзя.
- **ADMIN** — студия контента (квизы, раунды, реклама).

Показ на ТВ открывается **паролем экрана** (`TV_PASSWORD`, демо `show123`), не аккаунтом. Шоу само стартует после первого игрока и крутится по кругу. Код комнаты виден на ТВ всё время игры. Подключение только по QR или ссылке `/join/код`.

## Подтверждение аккаунта

Два равноправных канала (достаточно одного):

1. **Почта** — ссылка `/verify?token=…`. Локально письма ловит **Mailhog** (http://localhost:8025).
2. **Web Push** — после регистрации PWA может подписаться на уведомления; сервер шлёт пуш «Подтверди аккаунт», клик открывает ту же verify-страницу.

Без подтверждения: можно играть как гость, нельзя писать рейтинг на аккаунт и нельзя публиковать квизы.

## Студия (админка контента)

В PWA, раздел «Студия» (только админ):

- Список своих квизов, черновик / опубликован.
- Карточка квиза: название, описание, время по умолчанию, публикация.
- **Раунды** — блоки шоу. У раунда: название, тип (`STANDARD` / `LIGHTNING` / `FINAL`), порядок, «показать рейтинг после раунда», необязательная реклама после раунда.
- **Вопросы** внутри раунда: текст, время, баллы, тип (один верный / правда-ложь), 2–4 варианта, цвет, какой верный.
- **Библиотека рекламы**: заголовок, текст карточки, URL картинки/ролика, длительность, CTA.

Последовательность эфира для одного квиза:

```
раунд N (титр)
  → вопрос → раскрытие → …
  → рейтинг раунда (если включён)
  → реклама (если привязана)
раунд N+1 …
финал (подиум) → запись рейтинга и медалей
```

## Конструктор аватара

Слойный SVG, круглая база. Сохраняется JSON в профиле:

- цвет кожи
- глаза: обычные / весёлые / подмигивание / строгие
- рот: улыбка / ухмылка / ухмылка вбок / «о»
- волосы: нет / короткие / кудри / длинные
- очки: нет / круглые / квадратные / тёмные
- лицо: нет / усы / борода
- румянец вкл/выкл

Тот же компонент на ТВ, в лобби, в профиле и у медалек.

## Рейтинг

- **За игру** — таблица на ТВ после раунда и в финале.
- **В аккаунте** — партии, победы, подиумы, сумма очков, лучший счёт, лучший стрик, ELO-подобный `rating` (старт 1000).
- **Глобальная таблица** — топ подтверждённых игроков.

После финала, если игрок залогинен и подтверждён, сессия привязывается к `userId` и статистика обновляется.

## Достижения (медальки)

Каталог в коде (`packages/shared`), факт выдачи в БД. Рядом с аватаркой — до 3 значков.

| id | Название | Как получить |
|---|---|---|
| first_game | Дебют | Первая завершённая игра |
| first_win | Чемпион | 1 место |
| podium | Подиум | Топ-3 |
| streak_3 | В ударе | 3 верных подряд в одной игре |
| perfect_round | Без ошибок | Все вопросы раунда верно |
| speed | Молния | Верный ответ быстрее 2 с |
| games_10 | Завсегдатай | 10 игр |
| score_5k | Тяжеловес | ≥ 5000 очков за игру |
| author | Автор | Опубликовать квиз |

## Что ещё заложено (пункты, которые легко забыть)

- Гость vs аккаунт в одной комнате.
- Реконнект игрока по `playerToken`.
- JWT в localStorage PWA, `Authorization: Bearer` на REST; сокету при join передаём тот же токен.
- Черновик квиза нельзя выбрать для эфира.
- Публикация только если есть ≥ 1 раунд и ≥ 1 вопрос с верным вариантом.
- Ведущий из аккаунта не нужен. ТВ: пароль показа. Эфир сам листает сцены и после подиума начинает новый круг. Код/QR на экране всегда.
- Игрок заходит по QR или коду, в том числе в уже идущую игру.
- Таймер и очки только на сервере; правильный ответ на PWA до reveal не уходит.
- Mailhog + Redis + Postgres в docker-compose.
- VAPID-ключи для push в `.env`.
- Сброс пароля в этой итерации нет (можно следующей главой диплома).
- Загрузка файлов на диск нет: картинки вопросов/рекламы — URL.
- Лимит комнаты 50 игроков.

## Схема данных (итог)

`users`, `quizzes`, `rounds`, `questions`, `question_options`, `ads`, `game_sessions`, `session_players`, `session_answers`, `user_achievements`, `push_subscriptions`.

Убрана `quiz_ads`: реклама висит на раунде (`rounds.ad_id`).

## Этапы работ

1. План (этот файл).
2. Миграция Prisma + shared-типы.
3. Auth, почта, push.
4. REST студии.
5. Игровой автомат раундов/рейтинга/рекламы.
6. UI PWA (аккаунт, аватар, студия, таблица).
7. UI TV.
8. Seed, Mailhog, проверка сборки.
